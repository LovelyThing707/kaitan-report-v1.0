01

プロジェクト概要

教材「快単」の学習メソッドを忠実にアプリ化し、英単語を短時間で「絶対記憶（見聞きした瞬間に意味が出てくる状態）」にすることを目的とした、スマートフォン用学習アプリである。

  • 対応OS：iOS（14以降）／ Android（8.0 / API 23 以降）
  • 提供形態：端末内完結・オフライン動作・サーバ利用なし
  • 収録語数：約 2,201語（First stage 見出し語）
  • 開発：Flutter によるクロスプラットフォーム開発

MVP版では First stage を完成させる。Second stage（2番目以降の意味・派生語・反対語、医系単語、育成キャラクター）は枠のみ用意し、本MVPの対象外とする（「16. 対象外・将来拡張」参照）。

02

用語定義

用語定義
満点法（まんてんほう）OKした単語を出題から除外し、再チェックした単語のみを次の巡で再出題することを、全単語OKになるまで繰り返す学習方式。本アプリの中核ロジック。
巡目（じゅんめ）満点法における出題の周回。1巡目＝最初の出題、2巡目＝1巡目で再チェックした語のみ、…。
ブロック2,201語を48語前後ごとに区切った学習単位。全46ブロック。
OK意味が分かった単語に対する判定。出題リストから除外される。
再チェック意味が分からなかった単語に対する判定。次の巡で再出題される。
初回OKを除く各ブロックに最初に取り組んだ際にOKした単語を除外して出題する開始モード。
回転／ラップ指定範囲の全単語が全OKになり指定範囲終了に至ること。星評価の単位。
ステージFirst stage（見出し語の中心的意味）／ Second stage（2番目以降の意味・派生語等）。MVPはFirst stageのみ。
TTS💡 Text-to-Speech。端末標準の音声合成機能で英単語を読み上げる仕組み。

04

画面仕様

各画面について「目的／表示要素／操作／状態／遷移」を定義する。画面番号は解説書の丸数字に準拠する。レイアウトは片手操作・3秒チェックを最優先とし、主要ボタンは親指可動域（画面下部）に配置する。

4.1　① スタート画面

目的学習するステージを選択する起点画面。
表示要素アプリタイトル／ロゴ、First stage ボタン（5つの星表示を含む）、Second stage ボタン（「準備中」表示・5つの星表示枠）。
操作First stage タップ → ② 範囲指定画面へ。Second stage タップ → 「準備中」トースト表示（MVPでは遷移しない）。
状態各ステージボタンの下に星5個を表示（「8. 星評価」参照）。
遷移→ ② First stage 範囲指定画面。
Second stageは枠と「準備中」表示のみ用意し、将来の拡張をユーザーに示す（教材販売時のアピールにもなる）。

4.2　②③ 範囲指定画面

目的学習対象のブロックを選択し、開始モードを決めて出題を開始する。
表示要素46ブロックのボタンをグリッド配置（快単vol.1＝ブロック1〜23、vol.2＝ブロック24〜46）。各ブロックに番号と語ID範囲（例：「7：289〜336」）を表示。vol.1全体／vol.2全体の一括選択ボタン。スタート／初回OKを除く の開始ボタン。リセット ボタン。
操作・ブロックをタップで選択／選択解除（順不同・複数可）
・一括選択ボタンで該当vol全ブロックを一度に選択
・リセット：選択状態と当該範囲の学習記録をクリアし、全ブロックを白に戻す
・スタート：選択範囲の全単語を出題（前回記録をリセット）
・初回OKを除く：各ブロックで初回にOKした単語を除外し、再チェック対象のみ出題
状態（色）白＝未学習／リセット後、青＝選択中、薄い色（うす青）＝全OK完了。完了済み（薄色）ブロックと未学習（白）ブロックを同時選択可能。
遷移スタート または 初回OKを除く → ⑥ 問題画面。

補足：開始モードの動作差

  • スタート：選択範囲の記録を消去し、全単語を1巡目として出題する。
  • 初回OKを除く：各ブロックに最初に取り組んだ際にOKした単語を出題から除外する。白ブロック（学習履歴なし）にこのモードを適用した場合は、OK=0として全単語が出題される。

4.3　⑥ 問題画面

目的単語を提示し、意味を想起させる。3秒以内の判断を促す。
表示要素・単語（大きく表示）・品詞（他／自／名／形／副／前／接／間。複数品詞があれば併記）・問題番号（見出し№、例：№0341）・ステージ名（First stage）・スピーカーボタン（TTS再生）・意味・例文 ボタン・画面下部のカウンタ：残/総数・OK数・再チェック数（リアルタイム更新）
操作・画面表示時に発音音声を自動再生・スピーカーボタンで再度再生・意味・例文 タップ → ⑦ 解答画面。
状態カウンタは当該巡の進捗をリアルタイム反映。
遷移→ ⑦ 解答画面。

4.4　⑦ 解答画面

目的意味・覚え方を提示し、OK／再チェックを判定させる。
表示要素・単語、品詞、カタカナ読み・意味（意味1・意味2）・覚え方（ゴロ／語源／カタカナ／イメージ）・語源（源タグの内容、ある場合）・イラスト（💡 将来対応。MVPでは枠のみ／非表示）・例文（英・日。画面末尾に表示）・OK ボタン／再チェック ボタン（大きく配置）・画面下部の同カウンタ
操作・OK：当該単語を出題リストから除外し、即座に次の単語の⑥問題画面へ・再チェック：当該単語を次巡の再出題リストに残し、即座に次の単語の⑥問題画面へ・例文を参照してからOK／再チェックを押すことも可能。
状態当該巡の最後の単語に対する判定後は、結果表示画面へ自動遷移（「5. 満点法ロジック」参照）。
遷移→ ⑥ 問題画面（次の単語）／ 当該巡終了時 → ⑧ 結果表示画面。
操作速度を最大化するため、問題⇄解答の往復は画面遷移アニメーションを最短（100ms以下／実質無し）とする。

4.5　⑧⑩ 結果表示画面

目的当該巡の結果を提示し、次巡または範囲終了へ導く。
表示要素今回の結果：総数・OK数・再チェック数。次に進む ボタン。範囲再指定 ボタン。
操作・次に進む：再チェックした単語のみで次巡を構成し、⑥問題画面へ・範囲再指定：②範囲指定画面へ戻る。
状態当該巡で再チェックが0件（全OK）の場合は、本画面を経由せず（または経由後自動で）⑪ 指定範囲終了画面へ移行する。
遷移→ ⑥ 問題画面（次巡）／ ⑪ 指定範囲終了画面（全OK時）／ ② 範囲指定画面。

4.6　⑪ 指定範囲終了画面

目的範囲達成を祝福し、学習状態を確定する。
表示要素「頑張った！おめでとう！」等のメッセージ、お祝い演出（3〜5秒）。
操作演出再生後、自動的に①スタート画面へ戻る。
状態・選択していたブロックの色を完了（薄色）に変更・前回1巡目の再チェック記録は保持する（「初回OKを除く」用）・46ブロック全完了時も①スタート画面へ戻る（星評価が1回転分進む。「8. 星評価」参照）。
遷移→ ① スタート画面（自動）。
お祝い演出は、軽量・高画質で実装できるアニメーション（Rive/Lottie）を推奨。動画ファイル（mp4）をご支給いただく場合はそれを再生する形にも対応可能（ご確認事項 Q-5）。
05

満点法ロジック詳細（中核）

本アプリの価値を決定する中核ロジック。明確なステートマシン（💡 状態と遷移が定義された処理機構）として実装し、全パターンを検証する。

5.1　基本アルゴリズム

  1. 出題リスト ← 選択範囲の対象単語（モードにより初回OK語を除外）
  2. 巡目 ← 1
  3. 出題リストをランダム順に並べ、1単語ずつ問題画面に出題
  4. 各単語について判定：　OK → 当該単語をリストから除外／　再チェック → 「次巡リスト」に追加
  5. 当該巡の全単語を出題し終えたら、結果表示画面を表示
  6. 次巡リストが空（再チェック0件）→ 指定範囲終了画面へ（学習完了）／　残あり → 出題リスト ← 次巡リスト、巡目+1、③へ戻る

5.2　巡目進行の例（解説書④〜⑩：ブロック7+8＝96語）

巡目出題数OK再チェック
1巡目965640
2巡目402614
3巡目14104
4巡目440 → 全OK・指定範囲終了

5.3　検証観点（テスト項目）

  • 巡目進行（多巡にわたる除外・再構成の正確性）
  • ランダム出題（同一巡内で重複なく全単語が出題されること）
  • 全OKでの自動遷移
  • アプリ再起動後の巡の途中復帰
  • 複数ブロック選択時／白・薄色ブロック混在時の動作
  • 「初回OKを除く」適用時の動作
06

「初回OKを除く」仕様

目的既に習得済み（初回OK）の単語を省き、未習得語に集中して復習効率を高める。
定義各ブロックに最初に取り組んだ巡（初回）で OK と判定した単語を、次回以降の出題から除外する。
データ単語ごとに「初回判定結果（first_round_result）」を永続化する（ER図 word_progress 参照）。
白ブロック適用時学習履歴がないため除外対象なし。OK=0としてブロック内全単語を出題する。
保持タイミング⑪ 指定範囲終了時、前回1巡目の再チェック記録を保持する（解説書⑨）。

09

学習履歴・データ永続化仕様

端末内データベース（💡 SQLite）に保存し、アプリを閉じても学習状態を完全に維持する。詳細は ER図 を参照。保存対象は以下のとおり。

  • ブロックごとの状態（未学習／完了、完了日時）
  • 単語ごとの学習履歴（初回判定、直近結果、試行回数）
  • 学習セッション（選択ブロック、現在の巡目、各単語の巡内結果）— 中断・再開に対応
  • ステージごとの回転数（星評価）
  • 設定（選択中のステージ等）

データは2つに分離して管理する：①単語マスタ（読み取り専用・アプリに同梱） と ②学習履歴（書き込み可能）。これにより、将来「英検1級3000語」等の教材を追加する際は単語マスタを差し替えるだけで済み、利用者の学習履歴は影響を受けない（保守性・拡張性のための設計）。

11

音声仕様

  • MVPは端末TTS（💡 iOS／Android標準の音声合成）で英単語を読み上げる。音声ファイルは同梱しない（アプリ容量と保守性のため）。
  • 問題画面表示時に自動再生。スピーカーボタンで再再生。
  • 将来、ご支給の録音音源（例：kai-julie 音声）への差し替えにも対応できるよう、音声機能は内部的に分離して実装する。

非機能要件

区分要件
性能1単語のチェック3秒以内・再確認7秒以内を実現する操作性。問題⇄解答の遷移は実質無遅延（100ms以下）。
オフライン全機能がオフラインで動作。ネットワーク不要。
プライバシー個人情報・利用データを外部送信しない（サーバ・解析ツール不使用）。プライバシーポリシーは「データ収集なし」の最小構成。
対応OSiOS 14以降／Android 8.0（API 23）以降。
可搬性・保守性クリーンアーキテクチャ（💡 表示・ロジック・データの3層分離）。第三者開発者が短期間で把握できる構造。日本語コメント・設計ドキュメント整備。
データ堅牢性スキーマ確定後の変更でも学習履歴が失われないマイグレーション設計。

ご確認事項（着手前にご回答をお願いします）

#確認事項弊方の推奨
Q-1基本データ（Excel）の全2,201語版のご支給時期。5月末で承知。形式は現行Excelで可。
Q-2ブロック番号の定義：基本データExcelの「P番号」列は、解説書の46ブロック区分（48語区切り）と一致しません（サンプルではP番号1＝46語、P番号2＝50語）。アプリのブロック分けは解説書の語ID範囲（7.1）に従い、語IDから自動算出する方針でよろしいでしょうか。語IDから算出を推奨。
Q-3星評価の「1回転」の定義：46ブロック全完了で1回転という理解で正しいでしょうか。部分範囲のみの完了の扱いをご教示ください。46ブロック全完了＝1回転を推奨。
Q-4Second stageの問題タグ（名/形/動/類/反/塾 等）に表記揺れがあります。正規化対応表を弊方で作成しご確認いただく形でよろしいでしょうか（実装はSecond stageですが、データ設計に影響）。弊方作成→ご確認を推奨。
Q-5⑪お祝い演出は、弊方でアニメーション案を作成しますか／菊地様が動画（mp4）をご準備されますか。弊方でアニメ案作成を推奨。
Q-6覚え方イラスト2,201枚の供給方法・命名規則（例：0001.jpeg）。MVPでは「将来対応」枠とし、供給後に有効化する想定でよろしいでしょうか。Drive/Dropbox・連番命名を推奨。
Q-7品詞は8種（他/自/名/形/副/前/接/間）の想定でよろしいでしょうか。8種で設計。
